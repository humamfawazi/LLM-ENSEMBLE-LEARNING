# LLM prompts, parsing rules and parameters

All three LLM conditions use **qwen3.7-max-2026-06-08** (Alibaba Cloud Model Studio / DashScope, OpenAI-compatible chat completions API).
The templates below were generated by calling the same functions that produced the released outputs
(`code/legacy_code/nb06_prompt.py`, `code/legacy_code/rev04_baseline_prompt.py`), so the Indonesian text is verbatim.
English translations are provided for readers only; **they were never sent to the model**.

| Condition | Pairs sent | Prompt |
|---|---|---|
| Selective arbitration (Soft Voting + LLM-as-a-Judge) | 57 flagged pairs (split vote **or** margin < 0.15) | arbitration prompt |
| LLM-always (ablation) | all 560 test pairs | arbitration prompt (identical prompts share one cached response) |
| LLM-only (baseline, no ensemble information) | all 560 test pairs | LLM-only prompt |

## 1. Parameters

| Parameter | Value |
|---|---|
| Model snapshot | `qwen3.7-max-2026-06-08` (requested and returned model identical for all 1120 responses) |
| Sensitivity model (LLM-only only) | `qwen3-max-2026-01-23` (responses from an earlier run; see §8) |
| temperature | 0.0 |
| max_tokens | 256 |
| extra_body | `{"enable_thinking": false}` (thinking mode off) |
| Retries | up to 3 attempts per pair; wait `5 × 2^(attempt−1) + U(0, 1)` s between attempts |
| API key / endpoint | environment variables `DASHSCOPE_API_KEY` and `DASHSCOPE_BASE_URL` (never stored in code) |
| Cache key | SHA-256 over (model, messages, temperature, max_tokens, extra_body); identical requests reuse one response |

## 2. System prompt (verbatim)

```text
Kamu adalah verifikator label sentimen ABSA untuk teks Indonesia. Jawab HANYA dengan JSON yang diminta, tanpa teks tambahan.
```

English: *You are a sentiment-label verifier for ABSA of Indonesian text. Answer ONLY with the requested JSON, without additional text.*

## 3. Arbitration prompt (user message, verbatim template)

Placeholders: `{tweet_text}` = `text_v1` of the tweet (URLs and @mentions removed, whitespace collapsed);
`{aspect_description}` = aspect description (§5); `{proposed_label}` = weighted soft-voting label;
`{pred_*}` = seed-averaged prediction of each encoder. Labels are passed as the Indonesian label names in §6.

```text
Kamu adalah verifikator label sentimen. Berikut informasi sebuah tweet dan hasil voting 3 model AI.

Tweet: "{tweet_text}"
Aspek yang dinilai: {aspect_description}
Label yang diusulkan ensemble: {proposed_label}
Rincian suara 3 model: IndoBERT={pred_indobert}, XLM-RoBERTa={pred_xlm_roberta}, mBERT={pred_mbert}

Tugasmu: putuskan apakah label yang diusulkan sudah tepat (RETAIN) atau perlu diganti (REVISE).
Jika REVISE, sebutkan label yang benar dari salah satu: tidak_disebutkan, positif, negatif, netral.

Jawab HANYA dalam format JSON (tanpa teks lain, tanpa markdown code block):
",
{"decision": "retain" atau "revise", "final_label": "...", "reasoning": "alasan singkat 1 kalimat"}
```

> Note: the line `",` after "Jawab HANYA dalam format JSON …" is a stray artefact of the original f-string (`\n",`). It is kept
> verbatim because it was part of every prompt sent to the model.

English translation:

```text
You are a sentiment-label verifier. Below is information about a tweet and the voting result of 3 AI models.

Tweet: "{tweet_text}"
Aspect being assessed: {aspect_description}
Label proposed by the ensemble: {proposed_label}
Votes of the 3 models: IndoBERT={pred_indobert}, XLM-RoBERTa={pred_xlm_roberta}, mBERT={pred_mbert}

Your task: decide whether the proposed label is correct (RETAIN) or needs to be replaced (REVISE).
If REVISE, give the correct label from one of: tidak_disebutkan, positif, negatif, netral.

Answer ONLY in JSON format (no other text, no markdown code block):
",
{"decision": "retain" or "revise", "final_label": "...", "reasoning": "short 1-sentence reason"}
```

## 5. Aspect definitions (inserted as `{aspect_description}`; also `sentence_b` of the encoder input)

| Aspect key | English name | Description (verbatim) | English translation |
|---|---|---|---|
| `pola_konsumsi` | Consumption pattern | Tweet ini membahas pola konsumsi makanan atau minuman | This tweet discusses food or beverage consumption patterns |
| `aktivitas_fisik` | Physical activity | Tweet ini membahas aktivitas fisik atau olahraga | This tweet discusses physical activity or exercise |
| `akses_layanan_kesehatan` | Healthcare access | Tweet ini membahas akses terhadap layanan kesehatan | This tweet discusses access to health services |
| `pengetahuan_pengobatan` | Treatment knowledge | Tweet ini membahas pengetahuan atau pengobatan penyakit | This tweet discusses knowledge or treatment of the disease |

Aspect keyword lists used for silver-label aspect detection: `resources/aspect_keywords.json`.

## 6. Allowed labels

| Label (as used in prompts and files) | Integer id | English |
|---|---|---|
| `tidak_disebutkan` | 0 | not mentioned (aspect absent) |
| `positif` | 1 | positive |
| `negatif` | 2 | negative |
| `netral` | 3 | neutral |

## 7. Expected JSON and parsing rules

Arbitration / LLM-always: `{"decision": "retain" | "revise", "final_label": "<label>", "reasoning": "<one sentence>"}`
LLM-only: `{"final_label": "<label>", "reasoning": "<one sentence>"}`

Parsing (`call_llm`, `code/legacy_code/nb06_call_llm.py`, applied identically to all conditions):

1. Strip whitespace; if the response starts with a markdown fence (```), drop every line that starts with ```.
2. Take the substring from the first `{` to the last `}` and parse it with `json.loads`.
3. `decision` is lower-cased; any value other than `retain`/`revise` (or a missing field) becomes `retain`.
4. `final_label` is lower-cased; any value outside the four labels (or a missing field) becomes `tidak_disebutkan`.
5. `reasoning` is kept as returned (string).
6. No JSON object, or a JSON parse error → the attempt fails and is retried (§1).
7. The parsed `final_label` is used as the arbitrated label regardless of `decision` (in this run 2 responses said
   `revise` but returned the ensemble's own label; they are kept as returned).

Fallback after all attempts fail to yield parsable JSON:

* Arbitration / LLM-always: `decision = retain`, `final_label` = weighted soft-voting label, `reasoning = "LLM call failed — fallback to soft vote"`.
* LLM-only: `final_label = tidak_disebutkan`, `reasoning = "LLM call failed"`.
* API errors (quota, authentication, unknown model, connection) do **not** trigger the fallback: the run stops and is resumed later
  from the response cache, so no pair is silently labelled by the fallback.

Observed in the released run: 1120 unique API responses; 1177 logged requests across the three conditions
(57 + 560 + 560), each answered and parsed on the first attempt; 0 fallbacks (column `status` = `ok` for every pair).

## 8. Model snapshot change

The pre-registered snapshot `qwen3-max-2026-01-23` was retired by the provider (HTTP 404 `model_not_found`) before any LLM output was
obtained on the test set in this revision round. All three LLM conditions were therefore run with `qwen3.7-max-2026-06-08`, with no other change
to prompts, parameters or parsing. LLM-only responses obtained earlier with `qwen3-max-2026-01-23` (same prompts and parameters) are
released as a sensitivity analysis only (`outputs/llm_only_qwen3max_sensitivity.csv`); they were not used by any main result.
